# 代码体检与背景整理

记录时间 2026-11-25。统计范围为前端 `src` 中的 Vue、TypeScript 和 CSS，以及后端业务 Java。测试、数据库迁移和构建产物分别统计。行数包含空行与注释，不能单独作为复杂度或质量评分。

## 结论

目前是功能较丰富、规模可控的单体项目。当前前端 55 个源码文件、5035 行，后端业务 29 个文件、2689 行，共 7724 行。没有发现需要因为文件规模而立即重写的业务模块。本轮主要处理背景附带的跨框架依赖和已经无页面引用的旧展示样式。

## 构建前后对比

在同一工作区，先构建旧版本，再修改源码、同步锁文件并重新构建。单位采用十进制 kB。

| 指标 | 整理前 | 整理后 | 变化 |
| --- | ---: | ---: | ---: |
| 全部路由 JavaScript | 558.7 kB | 306.1 kB | 减少 45.2% |
| JavaScript 的 gzip 估算 | 206.3 kB | 126.5 kB | 减少 38.7% |
| 全部 CSS | 54.2 kB | 44.3 kB | 减少 18.3% |
| CSS 的 gzip 估算 | 13.0 kB | 11.1 kB | 减少 14.8% |
| 运行依赖 / 开发依赖 | 8 / 8 | 3 / 5 | 删除 8 个直接依赖，二维码类型移入开发依赖 |
| 全局样式文件 | 985 行，42.7 kB | 914 行，37.2 kB | 删除无引用的旧展示样式及被覆盖的定义 |

这些数字是所有路由产物的总量，并非每次打开一个页面都会传输的大小。路由按需加载，浏览器缓存也会影响实际流量。gzip 数值由 Node 计算，仓库的 Nginx 站点配置未显式开启 gzip，上线时应确认服务器压缩配置。

云雾算法自身只有约 6.7 kB 的构建代码，gzip 后约 2.8 kB。原来的额外体积来自 React、React DOM、Tailwind、类名合并工具及其类型依赖。保留同一套着色器，将管理生命周期的代码改为 Vue 后，效果可以继续使用。

## 背景如何共用

`App.vue` 只挂载一份 `BackgroundShell.vue`。路由在 `main.ts` 的 `meta.background` 声明模式，没有声明的路由使用详情模式。云雾算法独立在 `lib/cloudRenderer.ts`，需要动画时才下载。

| 模式 | 页面 | 显示与开销 |
| --- | --- | --- |
| home | 首页 | 完整云雾，绘制频率上限 30 帧，画布最多约 100 万像素 |
| public | 找座位、约服务、我的安排 | 低透明度慢速云雾，上限 20 帧，画布最多约 65 万像素 |
| detail | 预约详情、登录注册、聊天等 | 静态淡云与渐变，表单中间保持清楚 |
| workspace | 商家、员工、平台工作台 | 静态浅蓝渐变 |

宽度不超过 760px、粗指针触屏、系统选择减少动态效果或浏览器省流量时使用 CSS 静态背景。页面隐藏时停止绘制，切换到静态模式时销毁渲染资源。WebGL 不可用、上下文丢失或背景模块加载失败时仍有静态背景。

原有按钮、首页卡片、表单和业务接口继续使用现有规则。删除了不再需要的 React 封装、演示入口、云雾专用 Tailwind 样式和类名工具，着色器保留在新渲染模块。移除的五份源文件另存于本地 `.local/background-before-20261125.json`，便于对照与恢复，不参与构建。

## 模块职责和答辩路线

| 模块 | 可以这样解释 |
| --- | --- |
| 前端路由与会话 | `main.ts` 负责页面入口，`session.ts` 同步当前身份，`SiteHeader.vue` 根据身份给出入口；后端仍独立校验每个操作的权限 |
| `account` | 管理商家、员工、读者和平台管理员身份、登录会话及员工邀请 |
| `shop` | 管理店铺资料、服务项目、品牌展示和平台审核；`Campus` 负责公开服务目录 |
| `schedule` | 管理员工可提供的服务、每周排班和停约日期，为空档计算提供约束 |
| `booking` | 根据排班计算服务空档，创建和取消预约，用事务及数据库约束防止重叠，保存订单快照 |
| `library` | 管理校园空间、座位、楼层位置、开放时段、座位预约和自动到期；批量排座与回收站保持历史预约可追溯 |
| `social` | 根据读者身份和同馆预约找人，维护聊天邀请、会话、未读和安静提醒，发送消息前核对双方会话权限 |
| 迁移与测试 | Flyway 按顺序演进数据库；集成测试检查并发预约和状态迁移，这些内容不会随网页下载 |

讲解服务预约时，可以从 `Reserve.vue` 选择服务和员工开始，沿公共接口进入 `Bookings`，说明排班检查、事务和重叠约束，最后回到“我的安排”。

讲解座位预约时，可以从 `LibraryReserve.vue` 和 `SeatMap.vue` 开始，进入 `Libraries`、`SeatReservations` 和 `SeatLifecycle`，说明可用时段、同座冲突及到时自动生效和释放。

讲解聊天时，重点说明“有资格找到对方”和“对方同意聊天”是两次独立判断。待处理邀请不会因长时间未点击而自动拒绝，所有相关操作都检查当前读者是否属于该会话。

## 全局样式清理增补

背景整理后，全局样式又从 938 行减至 914 行，源码减少 1,342 字节。移除了无引用的旧座位网格、旧登录入口、旧页面区块及未使用的主题变量；相同选择器被后续规则完全覆盖的属性保留最终定义，原有媒体查询和优先级顺序继续保留。没有改页面模板或业务脚本。

在 12 个真实页面与 390、768、1440px 三种宽度下，逐元素对比清理前后的布局、字体、颜色、间距、边框和伪元素等样式，36 组结果一致；生产构建通过。清理前样式备份在 `.local/style-before-consolidation.css`，可用于恢复。

## 下次如何复查

在 `frontend` 目录执行：

```sh
npm run build
npm run size
```

也可以在项目根目录执行 `node scripts/code-health.mjs --json` 查看详细数据。脚本只读取源码、锁文件和已有构建产物；源码更新后先构建，避免统计旧产物。

`node_modules`、Maven `target`、`.local` 截图及本地验证脚本是开发文件，不是网页下载内容。生产前端由 Dockerfile 只复制 `dist` 到 Nginx，后端由服务进程运行，访问者不会下载 Java 源码。
