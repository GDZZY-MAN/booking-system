# 有约 · 校园预约平台

首页分为三个独立入口：「找座位」「约服务」「我的安排」。学生浏览图书馆、自习室和研讨间的空间信息并选座，查找校园周边服务并预约人员与时段，在个人时间表统一查看今天、本周和全部预约。服务商、员工和空间管理员通过各自入口管理配置与订单。

空间管理员可在「空间展示信息」设置类型、安静程度、地点与规则；楼层、插座和靠窗数量由开放座位实时汇总。服务商可在「服务目录信息」设置分类和地点，发布后进入公开服务目录。未填写的信息与暂无评价会如实显示，不生成虚构场所或评价。

空间与服务可公开浏览。提交预约时使用校园账号，登录后会恢复仍可用的选择。座位与服务都进入「我的安排」，服务联系方式按次填写。历史访客订单继续保留在所属店铺。

## 本地运行

安装 Docker 和 Docker Compose 2.24.4 或更高版本，把 `.env.example` 复制为 `.env`，将 `POSTGRES_PASSWORD` 换为随机强密码。项目名 `youyue` 已固定，支持中文目录。

```sh
docker compose up -d --build
docker compose ps
```

打开 `http://localhost:8080`，健康检查是 `http://localhost:8080/health`。如端口被占用，修改 `.env` 的 `WEB_PORT`。首次启动由 Flyway 创建表。

分开开发时，用 Java 21、Maven 3.9、Node 22 和 PostgreSQL 17。先准备一个本地数据库，账号需要在该库创建 `btree_gist` 扩展的权限。

Windows 上 Docker 未启动时，也可以通过 PostgreSQL 安装程序安装数据库。在 SQL Shell 以数据库管理员身份运行下面两条语句，再用同一个密码启动 Java。

```sql
CREATE ROLE shopbooking LOGIN PASSWORD '<你的开发库密码>';
CREATE DATABASE shopbooking OWNER shopbooking;
```

```powershell
$env:DB_URL = 'jdbc:postgresql://127.0.0.1:5432/shopbooking'
$env:DB_USER = 'shopbooking'
$env:DB_PASSWORD = '<你的开发库密码>'
mvn.cmd -f backend/pom.xml spring-boot:run
```

另开终端进入 `frontend` 后运行 `npm ci`、`npm run dev`，访问 Vite 打印的地址。若调整了 Java 的 `PORT`，在启动 Vite 前设置 `BOOKING_API_ORIGIN`，例如 `http://127.0.0.1:18080`。前端构建运行 `npm run build`，后端打包运行 `mvn -f backend/pom.xml package`。

Windows 本地预览也可以在项目目录运行 `powershell -File scripts/start-preview.ps1 -OpenBrowser`。脚本把前端作为独立后台进程启动，固定使用 `http://127.0.0.1:15173`，重复运行会复用已有预览，并检查后端连接。后端仍按上面的方式启动；预览日志在 `.local/preview-*.log`。电脑重启后需要重新启动本地服务。

手机局域网测试时，在同一 Wi-Fi 或手机热点下运行 `powershell -File scripts/start-preview.ps1 -Port 15174 -ListenAddress <电脑局域网IPv4>`，再用手机访问输出的网址。电脑更换网络后需按新地址重新启动。默认预览仍只监听本机；局域网模式只用于可信网络中的临时测试，正式部署使用 HTTPS。预约与消息的请求键兼容局域网 HTTP，保持安全随机生成和重复提交识别。

## 一次完整演示

服务时长支持自定 1–480 分钟，员工排班的开始、结束时间可精确到分钟。停约日期可在日历中多选，也可以输入起止日期批量添加；重复日期自动去重，最多 366 天。停约只影响新预约，已确认预约保留。

1. 注册一家虚构店铺，例如「青禾工作室」，设置唯一链接标识。
2. 添加 45 分钟的「手部护理」和 30 分钟的「修型」。添加两位员工，给两人分配服务和第二天的排班。
3. 在「店铺与入驻审核」提交申请，平台管理员审核通过后，服务进入公开目录。用两个独立浏览器会话选择同一员工的重叠时段同时提交，只有一笔确认。
4. 店主为第一位员工生成邀请，在独立会话中打开并注册。员工只看到分配给自己的订单。店主取消一笔预约后，顾客可重新查询并预约仍符合排班的时段。

在店主后台「店铺展示」可以选择主题、上传店标和封面，以及填写地址、营业说明和预约须知。外观发布与入驻审核分别管理。通过审核的店铺可在「分享推广」复制预约地址、下载二维码。

## 平台管理员

商家管理支持“删除商家”，经确认后移入回收站并停用。存在尚未结束的已确认预约时不能删除，应先处理预约；历史订单、账号和链接标识保留，不释放用户名或链接标识。入驻状态选择“已删除（回收站）”可恢复，恢复后为待完善且未发布，须重新提交入驻审核。删除后商家和员工不能继续登录或使用已有会话操作后台。

首页底部「平台管理」进入 `/admin`，独立登录地址 `/admin/login`。设置 `PLATFORM_ADMIN_USERNAME` 和 `PLATFORM_ADMIN_PASSWORD` 后启动后端，可创建管理员；重复启动不会覆盖既有密码，不提供公开注册或把商家自动升级为管理员。Docker Compose 读取同名 `.env` 配置。管理员可以审核、驳回、下架、恢复商家及查看订单，并统一创建、切换管理多个校园空间。

商家与空间按资源类型隔离，管理员身份为 ADMIN，商家为 OWNER，员工为 EMPLOYEE，学生为 READER。旧场馆及预约链接、座位和历史记录保留；旧场馆 OWNER 账号不获得平台管理权限，需改用独立的平台管理员登录。

## 图书馆与自习室座位预约

1. 从首页「平台管理」登录，在「校园空间管理」添加或选择场馆，分别维护每个图书馆、自习室和研讨间。场馆不再独立注册账号。旧 `/library-admin` 页面会重定向到平台管理，原场馆 OWNER 账号不能继续管理场馆。
2. 先保存开放时间和时段长度，再添加座位、楼层与设施，最后在「开放时间」勾选「开放读者预约」并保存。
3. 学生从「找座位」选择场馆，或通过管理员在「分享与二维码」中复制的场馆链接直接选座。
4. 预约时段开始后自动生效，无需签到。读者可在「我的安排」查看记录、开始前取消、时段内提前结束；到期自动释放座位。

选座页提供可点击的二维平面图，支持楼层切换、缩放和手机横向滚动。管理员编辑座位时可以指定楼层、行（1–20）和列（1–12）；同楼层不能重复占用一个位置，未填写坐标的历史座位自动排列。入口和窗边装饰为示意。

### 广东海洋大学湖光校区示例

学校 2023 年公开材料提到一楼学习大厅、二楼智慧服务空间和 2–7 楼阅读及研讨空间。由于未获得当前逐座平面图，本项目的两层 48 席示例使用模拟编号、位置和设施，页面附有资料来源与示例说明。资料记录见 [馆舍参考说明](docs/gdou-library.md)。

本地演示实例启动后，可设置专用演示管理员凭证，再执行初始化脚本。脚本只操作标识为 `gdou-huguang-demo` 的专用演示场所，重复运行补充缺少的示例座位并恢复演示营业时间。

```powershell
$env:GDOU_DEMO_USERNAME = '<专用演示管理员账号>'
$env:GDOU_DEMO_PASSWORD = '<至少8位的演示密码>'
node scripts/gdou-demo.mjs http://127.0.0.1:15173
```

打开 `/library/gdou-huguang-demo`，选择日期和时段，在楼层图点座位，再通过读者账号提交预约。演示数据保存在本项目数据库中。

默认规则是今天起七天内预约、每个读者同时一笔有效预约。无需签到，不设置迟到或爽约处罚。后台每分钟按预约时间更新状态，预约操作前也会校准状态；到期自动释放座位。修改营业时间或停用座位只影响新的预约。读者账户关联固定内部 ID，手机号验证后续可绑定到该身份并延续记录。当前自主注册适用于演示和小范围试用，一个人可以创建多个账号。

### 馆内交流

预约成功后即可进入「我的座位预约 → 馆内交流」，无需等待预约时段开始。默认显示「可联系读者」列表，可搜索昵称、座位或区域并直接邀请聊天；也可以切换「座位图选人」。两种入口共用选中对象，座位图会定位到所选读者的楼层。列表显示同馆尚未结束预约、允许新邀请的其他读者，包含未来日期；同一座位不同日期的预约人分别列出，并标注预约时间。座位图可按预约时段筛选，邀请绑定具体预约人。已屏蔽的对象不会显示为可联系。聊天仍需对方接受邀请。安静提醒仅在双方预约时段内开放。消息中心收到的提醒隐藏发送账号和来源座位，后台仍保存发送记录；提醒每 30 分钟合并一次。

读者在「消息与聊天」接受邀请后开始私聊，可设置昵称、关闭新邀请、撤回自己发出的待处理邀请、结束会话或屏蔽对方。待处理邀请会一直保留，预约结束后仍可由接收方决定是否接受；它不会因为长时间未操作而自动显示为拒绝。读者登录后，任何页面右下角都会固定显示新的聊天邀请，可直接接受、拒绝或打开消息页处理。微信号需手动填写并确认分享。已接受的会话绑定原来两位读者，座位换人后后续使用者无法读取。消息中心和浮动消息入口每 15 秒静音更新，网络中断时保留现有页面，恢复后可重试。短信或浏览器推送尚未接入。

预约并发和时间规则的 PostgreSQL 集成测试使用独立临时 schema，需要测试数据库允许创建 schema 和扩展。该测试会在结束后删除自己创建的 schema。PowerShell 中运行以下命令，数据库连接替换为你的专用测试库。

```powershell
$env:SEAT_TEST_DB_URL = 'jdbc:postgresql://127.0.0.1:5432/shopbooking'
$env:SEAT_TEST_DB_USER = 'shopbooking'
$env:SEAT_TEST_DB_PASSWORD = '<测试数据库密码>'
mvn.cmd -f backend/pom.xml test
```

在专用测试站点运行回归测试，运行环境需配置该站点的 `PLATFORM_ADMIN_USERNAME` 和 `PLATFORM_ADMIN_PASSWORD`。脚本创建虚构的店铺、读者和订单，并以测试管理员身份审核店铺。

```sh
node scripts/smoke.mjs http://127.0.0.1:8080
```

## 代码体检与背景

全站使用同一个背景组件，首页展示完整云雾，目录页面弱化显示，预约详情和工作台使用静态背景。手机、减少动态效果和省流量模式使用静态背景；云雾渲染代码按需下载，不再额外引入 React 或 Tailwind。

在 `frontend` 中先执行 `npm run build`，再执行 `npm run size` 可查看代码规模、全部路由产物与 gzip 估算。详细对比、维护重点和答辩模块说明见 [代码体检记录](docs/code-health.md)。

## 模块和预约调用路径

- `account` 管理会话、账号与员工邀请。 `shop` 管理店铺和服务。 `schedule` 管理员工、服务分配与排班。 `booking` 管理空档、预约与取消。模块通过业务服务协作，顾客端、商家后台和员工后台使用独立页面。接口见 [API 契约](docs/api.md)。
- 顾客提交时，`Reserve.vue` 发送服务、员工、开始时间及请求键。 `PublicController` 将请求交给 `Bookings`。事务内共享店铺配置锁，防止校验到写入之间排班被修改。 `booking_no_overlap` 约束用时间区间拦住重叠订单，冲突由 `ApiErrors` 转为 409。订单保存服务和员工名称快照，后续修改排班或服务仍可查看历史记录。
- 增加提醒时，可让提醒模块独立读取已提交订单或自行维护发送任务，失败只在提醒模块中重试。新增数据库变更使用下一条 Flyway 迁移，完成后重跑预约测试。

答辩练习是将 `Bookings` 中的 `BOOKING_DAYS` 由 30 改为 14，同时调整顾客日期控件上限。用今天起第 14 天和第 15 天验证前后端边界是否一致。

## 上线、备份与恢复

### Linux 云服务器与 HTTPS

1. 将源码传到服务器，安装 Docker Engine 和 Compose。准备固定公网 IP 或可用域名，允许 Web 端口 80、443。保持数据库和 Java 端口仅在容器网络内。使用中国内地节点前，按服务商说明完成适用的备案流程。
2. 将 `.env` 的 `PUBLIC_HOST` 设为证书对应的 IP 或域名。无域名时，用 Certbot 5.4 或更高版本申请 IP 证书。先在宿主机腾出 80 端口，创建续期使用的 webroot，再申请证书。使用域名时将 `--ip-address <PUBLIC_HOST>` 换为 `-d <PUBLIC_HOST>`。

   ```sh
   sudo mkdir -p /var/www/youyue-acme
   sudo certbot certonly --standalone --preferred-profile shortlived --ip-address <PUBLIC_HOST>
   docker compose -f compose.yml -f compose.https.yml up -d --build
   ```

3. 配置 Certbot 使用 webroot 续期并重载 Nginx。把路径替换成服务器上的绝对路径。检查 Certbot 安装提供的定时任务已启用。

   ```sh
   sudo certbot reconfigure --cert-name <PUBLIC_HOST> --webroot -w /var/www/youyue-acme \
     --deploy-hook 'docker compose --project-directory /opt/youyue -f /opt/youyue/compose.yml -f /opt/youyue/compose.https.yml exec -T web nginx -s reload'
   sudo certbot renew --dry-run --run-deploy-hooks
   ```

4. 用手机流量检查 `https://<PUBLIC_HOST>/health`、登录、店铺链接和顾客预约。公网演示用虚构联系方式。把网站地址和可访问的 GitHub 仓库地址提交给熊文睿。

若用本机加穿透，使用基础 Compose 并在 `.env` 设置 `COOKIE_SECURE=true`。让穿透服务将稳定 HTTPS 地址指向回环地址的 Web 端口，保持电脑在线，验收后再提供地址。Vite 开发服务用于本地开发。

### 备份与恢复

```sh
sh scripts/backup.sh
sh scripts/verify-backup.sh backups/<文件名>.dump
```

在服务器计划任务中每天执行备份脚本，并通过受控渠道复制到独立存储。脚本将备份恢复到同一数据库服务下一个独立临时数据库，核对订单表和冲突约束，再清理临时库。核对实际订单数量及近期订单后再恢复生产数据，恢复到新库并验证后切换连接。

检查健康端点和 `docker compose logs backend` 中的请求编号，定位数据库断开或请求失败。升级前备份并保留旧镜像。部署后运行核心预约流程，重启容器后再次验证旧订单和链接。
